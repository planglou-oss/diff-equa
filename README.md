# Yotsuba’s EE Math I

React + TypeScript frontend และ Go backend สำหรับคลังข้อสอบ 427 ข้อ ใช้สีส้ม/เขียว มาสคอต การ์ด และตำแหน่งแชตจาก HTML เดิม

## เริ่มใช้งานบน Windows

ดับเบิลคลิก `run.bat` สคริปต์จะ build frontend/backend และนำเข้าข้อมูลครั้งแรกอัตโนมัติ แล้วเปิดเบราว์เซอร์ไปที่ http://127.0.0.1:8080 เมื่อเซิร์ฟเวอร์พร้อมใช้งาน กด Ctrl+C เพื่อหยุด

เครื่องที่ใช้พัฒนาในงานนี้มี Go/npm แบบ portable ใน `.tools/` อยู่แล้ว เครื่องใหม่ต้องติดตั้ง Node.js 22.12+ พร้อม npm และ Go 1.26+ ก่อน แล้วติดตั้ง dependencies ตามขั้นตอนด้านล่าง `.tools/`, `node_modules/`, build และข้อมูลส่วนตัวไม่อยู่ใน source control

## เครื่องมือช่วยเรียน

- **เรียงปีข้อสอบ**: เลือก “ปีน้อย → มาก” หรือ “ปีมาก → น้อย” ในแถบเรียงลำดับ ระบบเรียงทั้งผลค้นหาก่อนแบ่งหน้า ทำงานร่วมกับตัวกรองเดิม และจำผ่าน URL/การกลับมาเรียนต่อ หากปีเท่ากันเรียงตามหัวข้อและเลขข้อ

- **ฝึกทำข้อสอบ**: เลือกหัวข้อ จำนวน 1–50 ข้อ และเวลา 1–180 นาที สุ่มข้อไม่ซ้ำ เลือกตัดข้อที่เข้าใจแล้วหรือเลือกเฉพาะรายการโปรดได้ ระหว่างทำซ่อนเฉลย คำใบ้ ข้อความ OCR และแชตในหน้าชุดฝึก
- **จับเวลาและทำต่อ**: เวลาอิง timestamp จึงเดินต่อแม้เปลี่ยนหน้าหรือปิดเบราว์เซอร์ เมื่อหมดเวลาจะจบชุดฝึกโดยเก็บคำตอบไว้ เปิดเฉลยได้หลังจบ; หากกลับมาเปิดหลังหมดเวลา ระบบจบที่ deadline เดิม
- **ความคืบหน้า**: สถานะยังไม่ทำ / กำลังทบทวน / เข้าใจแล้ว, รายการโปรด, โน้ต, ตัวเลือกคำตอบ และ checklist เก็บใน localStorage ของเบราว์เซอร์และเครื่องนี้ ไม่ใช่บัญชีที่ sync ข้ามอุปกรณ์ การล้างข้อมูลเว็บไซต์จะลบข้อมูลส่วนนี้ ถ้าบันทึกไม่ได้แอปจะแจ้งเตือน
- **กลับมาเรียนต่อ**: จำตัวกรอง ตำแหน่งรายการ ข้อล่าสุด เฉลยที่เปิด ระดับคำใบ้ และขั้นคำอธิบายที่กำลังอ่าน พร้อมชุดฝึก/คำตอบที่ยังทำไม่จบ เก็บประวัติชุดฝึกที่จบล่าสุด 10 ชุด
- **สูตรและคำใบ้**: มีสูตร/เงื่อนไข จุดที่มักพลาด และแนวทางตรวจคำตอบครบ 9 หัวข้อ คำใบ้เปิดทีละระดับ ข้อ 1–2 ของหัวข้อแรกมีคำใบ้เฉพาะข้อ ส่วนข้ออื่นระบุว่าเป็นแนวทางตามหัวข้อ
- **เฉลยทีละขั้น**: ใช้คำอธิบาย AI เดิม 10 ข้อโดยแบ่งตามหัวข้อย่อยและเปิดทีละขั้น สำหรับข้อที่ยังไม่มี ใช้ปุ่มถาม AI อธิบายทีละขั้นได้เมื่อเปิดใช้ AI
- **ตรวจคำตอบแบบ 4 ตัวเลือก**: แทนช่องพิมพ์คำตอบทั้งในแผงช่วยเรียนและชุดฝึกด้วยตัวเลือก ก/ข/ค/ง ที่ต่างกันเล็กน้อย ตรวจจาก answer key ที่เทียบภาพเฉลยต้นฉบับ ไม่เรียก AI ในคลังโจทย์กด “ตรวจคำตอบจากเฉลย”; ในชุดฝึกแสดงคะแนนและเหตุผลหลังจบเท่านั้น พร้อมลิงก์ภาพต้นฉบับ การประเมินสถานะความเข้าใจยังเลือกเอง
- **ความพร้อมของตัวเลือก**: มี answer key 10 ข้อจากคลัง 427 ข้อ ครอบคลุม 9 หัวข้อ (หัวข้อแรกข้อ 1–2 และข้อ 1 ของหัวข้อ 2–9) หัวข้อ Fourier Transforms ข้อ 1 ฝึกเฉพาะข้อย่อย (b) ตามข้อความกำกับ ข้ออื่นยังไม่มีตัวเลือกที่ตรวจทานแล้ว จึงไม่สร้างคำตอบจาก OCR อัตโนมัติ ใช้ตัวกรอง “เฉพาะข้อที่มี 4 ตัวเลือก” เพื่อหาข้อพร้อมฝึก ชุดฝึกใหม่สุ่มเฉพาะกลุ่มนี้และอาจมีน้อยกว่าจำนวนที่ขอ
- **บันทึกคำตอบและคะแนนรุ่นเดิม**: ตัวเลือกผูกกับ ID และ version ของเฉลย จึงไม่เปลี่ยนความหมายหลังรีเฟรช ข้อความคำตอบเก่ายังอยู่ในข้อมูลเดิม แต่ไม่แปลงเป็นตัวเลือกหรือหักเป็นข้อผิด ชุดฝึกที่เปิดจากประวัติจะแยกข้อที่ตรวจไม่ได้ออกจากตัวหารคะแนน
- **แจ้งข้อผิดพลาด**: อยู่ในแผงสูตร/คำใบ้ของแต่ละข้อ บันทึกลงตาราง `reports` บน Go server โดยไม่เปลี่ยน review status และไม่ส่งข้อความให้บุคคลภายนอกอัตโนมัติ
- **ค้นหาและอ่าน**: ค้นข้อความ OCR เดิม พร้อมแท็กไทย/อังกฤษ เช่น ลาปลาซ, สมการเชิงอนุพันธ์ และ convolution มีข้อความโจทย์ที่อ่านได้ด้วย screen reader, ปุ่มขยายภาพ และสถานะปุ่มสำหรับคีย์บอร์ด สูตร KaTeX bundle มากับแอป

ชุดฝึกเป็นเครื่องมือฝึกส่วนตัว ไม่ใช่ระบบคุมสอบ ข้อสอบและแนวทางอ่านได้เมื่อเปิด Go server โดยไม่ใช้ AI key; การถาม AI ต้องมีอินเทอร์เน็ต และ key อยู่ฝั่ง server

## คำสั่งมาตรฐานสำหรับเครื่องใหม่


## เปิด AI chat

คัดลอก `.env.example` เป็น `.env` ที่ root แล้วตั้ง `GEMINI_API_KEY` และ `GEMINI_MODEL` เป็นโมเดลที่บัญชีใช้งานได้ จากนั้น restart Go ไม่ต้อง build React ใหม่ ไม่ต้องใส่ key ในเว็บและไม่ใช้ key ที่เคยเก็บใน HTML เดิม

ถ้าไม่มีค่าทั้งสอง หน้าโจทย์ ภาพเฉลย และคำอธิบาย AI ที่นำเข้ายังใช้งานได้ ส่วน live chat แสดงสถานะยังไม่เปิดใช้งาน API key จะไม่ส่งให้ browser

สำหรับ Gemini 3 แอปตั้งระดับคิด `low` เป็นค่าเริ่มต้นเพื่อลดเวลารอก่อนเริ่มตอบ เปลี่ยนได้ด้วย `GEMINI_THINKING_LEVEL=low` / `medium` / `high` หรือ `default` เพื่อใช้ค่าของ provider (ระดับที่รองรับขึ้นอยู่กับรุ่นโมเดล; `minimal` ใช้ได้เฉพาะบางรุ่น) รุ่นก่อน Gemini 3 จะไม่ส่ง thinkingLevel เว้นแต่ตั้งค่าเอง คำตอบใช้ขีดจำกัด 4,096 tokens และ timeout 120 วินาที; งานที่ซับซ้อนหรือ provider หนาแน่นยังอาจใช้เวลานาน

AI chat ส่งเฉพาะข้อความโจทย์ของข้อที่เลือก คำถามล่าสุด และประวัติไม่เกิน 2 รอบ (4 ข้อความ งบประวัติรวม 4,000 ตัวอักษร) ไป Gemini ไม่แนบภาพโจทย์ ภาพเฉลย หรือคำอธิบาย AI ที่เก็บไว้ Prompt กำหนดให้ตอบเฉพาะสิ่งที่ถามอย่างกระชับ โดยยังถามต่อแบบ “ข้อนี้” ได้ ประวัติเต็มยังอ่านในหน้าต่างแชตได้ แต่โมเดลจะไม่เห็นบทสนทนาส่วนที่เก่าเกินงบ

เปิด “ข้อความโจทย์ที่ส่ง AI (แก้ไขได้)” ในแชตเพื่อตรวจหรือแก้สูตร/เงื่อนไขก่อนส่ง ข้อ 1–2 ของหัวข้อแรกมีข้อความที่ตรวจจากภาพแล้ว ส่วนข้ออื่นใช้ OCR เก่าที่ตัด metadata และส่วนเฉลยที่มี marker ชัดเจนออก ข้อความเหล่านี้ยังอาจผิด ขาดข้อมูลกราฟ หรือมีเฉลยที่ไม่มี marker ปน ห้ามถือว่าเป็น transcription ที่ตรวจครบแล้ว สามารถพิมพ์สูตรด้วย LaTeX หรืออธิบายกราฟในช่องนี้ได้ การแก้จะเริ่มบทสนทนาใหม่เมื่อส่งเพื่อป้องกันบริบทเก่าปน และบันทึกข้อความที่แก้เฉพาะ browser tab/session นี้

ระบบส่ง SSE keepalive ทุก 10 วินาทีระหว่างรอ พร้อมแยก error กรณีโควตา Gemini, key/สิทธิ์, โมเดล, timeout, คำตอบว่าง, token limit และ stream ขาด เมื่อเกิดข้อผิดพลาดระหว่างตอบจะเก็บส่วนที่ได้เป็น interrupted ไม่แสดงว่าตอบสมบูรณ์ หน้าต่าง Go แสดง request ID, error code, เวลารวม และเวลาถึงข้อความแรกเพื่อช่วยวิเคราะห์ โดยไม่ log key หรือข้อความแชต คำขอเก่าที่บันทึกเป็น AI_GENERATION_FAILED ไม่สามารถย้อนหาสาเหตุที่ไม่ได้เก็บไว้ได้

แต่ละ browser session เก็บประวัติแชตฝั่ง server แยกตามโจทย์และตรวจเจ้าของด้วย HttpOnly cookie เก็บ session 30 วัน จำกัด AI 30 คำขอต่อ session ต่อชั่วโมงและ 4 งานพร้อมกันทั้ง server คำตอบที่ยกเลิกหรือขาดการเชื่อมต่อแสดงว่ายังไม่สมบูรณ์และไม่ใช้เป็นประวัติในคำถามถัดไป การล้าง cookies จะทำให้เข้าถึงประวัติเดิมไม่ได้

## Development

เปิดสอง terminal:

```powershell
# Terminal 1 — จาก root
cd backend
go run ./cmd/server -data ../data -web ../frontend/dist -source ../exam201_solutions.html

# Terminal 2 — จาก root
cd frontend
npm run dev
```

เปิด http://127.0.0.1:5173 Vite proxy API และ media ไป Go; ถ้าตั้ง `.env` ให้รัน Go จาก root ด้วย executable ตามตัวอย่างแรก หรือส่ง environment variables ให้ process โดยตรง

## นำเข้าข้อมูลซ้ำ

หยุด server ก่อนแล้วรันจาก `backend/`:

```powershell
go run ./cmd/import-legacy -source ../exam201_solutions.html -data ../data
```

Importer อ่าน JSON โดยไม่ execute JavaScript แยกรูปด้วย SHA-256 ตรวจ PNG และคีย์ซ้ำ จับคู่คำอธิบาย AI ตามหัวข้อ/เลขในคลัง ใช้ upsert รันซ้ำแล้วไม่เพิ่มจำนวนหรือเปลี่ยน IDs และไม่ลบประวัติแชต หาก source ลบรายการออก importer จะไม่ลบรายการเก่าอัตโนมัติ

ข้อมูลต้นทางที่ตรวจแล้ว: 10 topic definitions, 427 questions, 854 image relationships, 10 AI explanations ภาพอาจ deduplicate จึงไม่ใช้จำนวนไฟล์ภาพเป็นจำนวนความสัมพันธ์

## โครงสร้าง

- `frontend/src/features/questions/` — search, filters, pagination, detail, solution panels
- `frontend/src/features/tutor/` — แชตและ streaming UI
- `frontend/src/components/` — render สูตร, ภาพขยาย, error notices
- `backend/internal/legacy/` — import HTML เดิม
- `backend/internal/storage/` — SQLite schema
- `backend/internal/httpapi/` — API, media, sessions, SSE
- `backend/internal/ai/` — Gemini text-only adapter ที่แทนด้วย mock provider ใน tests ได้
- `backend/internal/questiontext/` — ข้อความบริบทของข้อที่เลือกและสถานะ OCR/transcription
- `contracts/openapi.yaml` — REST/SSE contract
- `SYSTEM_DESIGN.md` — แบบระบบและแผนพัฒนาต่อ

## ขอบเขตปัจจุบัน

รัน Go instance เดียวกับ SQLite และ media บน persistent disk ก่อนเผยแพร่ให้คนทั่วไปใช้ key ร่วม ต้องเพิ่มระบบสมาชิกและโควตาที่ผูกผู้ใช้จริง Guest cookie ไม่ใช่ระบบสมาชิก หากใช้ reverse proxy ต้องส่ง SSE แบบไม่ buffer และตั้ง timeout มากกว่า 120 วินาที รวมทั้งตั้ง HTTPS และ Secure cookie อย่างถูกต้อง (แนะนำ terminate TLS ที่ Go หรือปรับ trusted proxy configuration ก่อนใช้งานภายนอก)

เก็บ backup ของ `data/eemath.db` และ `data/media/` เป็นชุดเดียวกัน โดยหยุด server ก่อนคัดลอกหรือใช้ SQLite backup API; ขณะรันมี WAL file และไม่ควรคัดลอกเฉพาะ DB แบบสด ๆ ภาพ mascot ที่นำเข้าอยู่ใน `data/mascot.png`

ระบบสมาชิก การ sync หลายอุปกรณ์ และ PWA offline เป็นงานระยะถัดไป ข้อความค้นหาเดิมยังมี OCR ของสูตรและเฉลยปน จึงซ่อนช่องค้นหา/ข้อความ OCR ในหน้าชุดฝึกที่กำลังจับเวลา ภาพเฉลยต้นฉบับและคำอธิบาย AI แสดงแยกแหล่งที่มาชัดเจน และคำอธิบาย AI เดิมยังมีสถานะ unreviewed

## เพิ่มข้อเลือกตอบในคลัง

แก้ `backend/internal/studycontent/choices.json` แล้ว build Go ใหม่ แต่ละรายการต้องมี questionId, SHA-256 sourceMediaId ของภาพเฉลย, prompt ที่ระบุขอบเขตคำถาม, options 4 รายการที่ต่างกันและมีคำตอบถูกเพียงหนึ่งข้อ, correctIndex, explanation และ feedback ของแต่ละตัวลวง ตรวจเทียบภาพต้นฉบับและตรวจการแทนกลับก่อนเพิ่ม ไม่ควรใช้ข้อความ OCR เป็น answer key โดยไม่ตรวจทาน

API ส่งเฉพาะตัวเลือกก่อนตอบ และคืนเฉลย/เหตุผลหลังส่งตรวจ หากภาพต้นฉบับเปลี่ยนจะปิดการตรวจข้อนั้นจนปรับ answer key; หาก version เปลี่ยน คำตอบเก่าจะแสดงว่าไม่สามารถตรวจเป็นคะแนนได้ ฟีเจอร์นี้ไม่ใช้ Gemini และใช้งานได้เมื่อปิด AI
